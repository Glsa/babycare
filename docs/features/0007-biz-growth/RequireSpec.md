# RequireSpec · 成长（生长 + 疫苗）

需求来源：PRD FR-7（生长）、FR-9（疫苗）、附录 A（免疫规划疫苗表）、UI 设计说明帧 06。范围切分与不做清单见 Request.md。

## FR-7 生长（原文要点）

- 三项独立录入：体重 kg 精确 0.005、支持按克输入；身高/长 cm 0.1；头围 cm 0.1
- 列表按时间倒序，显示来源（在家/体检）
- WHO 生长曲线 → V1.1（本 feature 不做）

## FR-9 疫苗（原文要点）

- 2021 版免疫规划表按生日自动生成计划，多剂次按月龄递推
- 每剂状态：未到月龄 / 待种 / 已种 / 不接种
- 已种记录：日期必填、接种点、名称剂次自动带出、备注批号
- 改期后续仍按月龄提醒
- 自费疫苗库默认隐藏 → V1 直接不展示
- 提醒（FR-13）延后

## 澄清结论（设计拍板）

| # | 问题 | 结论 |
| --- | --- | --- |
| Q1 | 体重怎么输到 0.005kg？ | 输入框按**克**（整数，如 6400），存 kg（6.4）。秤本身 5g 步进，不额外校验倍数，提示文案说明即可 |
| Q2 | 疫苗计划要不要像体检那样生成 AGENDA 记录？ | **不生成**。计划 = 纯函数按生日推导（22 剂固定表），只有用户操作（已种/不接种）才落 VACCINE_DOSE 记录。好处：改生日计划自动跟、无幂等管理、同步侧也免维护 |
| Q3 | 怎么把记录对回计划？ | VaccineDosePayload 加 `key` 字段（计划稳定标识，如 `b1`/`dtap3`），旧数据无 key 时按疫苗名+剂次兜底匹配 |
| Q4 | 不接种怎么表达？ | 同一条 VACCINE_DOSE 记录，payload `status="skipped"`；删掉这条记录 = 撤销不接种，回到待种/未到月龄 |
| Q5 | 「改期」是什么？ | 没有独立改期操作：晚种就是晚点标已种（填实际日期），计划日期永远按生日月龄推，天然满足「改期后续仍按月龄提醒」 |
| Q6 | 「下一剂」定义？ | 未完成（非已种、非不接种）的剂次里计划日期最早的那剂；显示名称+日期（+距今天数） |
| Q7 | 生长记录有备注吗？ | 不加。FR-7 只要求数值+来源；来源「体检」本身承担上下文 |

## 验收标准

1. 生长：只填体重能保存；数据卡显示三项各自最新值与日期；列表倒序、带来源；编辑/删除即时生效
2. 疫苗排期：22 剂、按生日月龄推（出生剂=生日当天）；生日变了排期跟着变（Q2 推导的必然结果）
3. 已种/不接种：录入后状态、进度（已种 X/22，不接种不计入）、下一剂即时更新；删除记录回到推导状态
4. 时间轴：生长/疫苗记录详情可编辑可删除
5. 纯函数（排期/状态/进度/生长最新值）单测全绿，assembleDebug 通过

## 已知边界

- 疫苗「待种」只做列表内状态标记，不推送提醒（FR-13 延后）
- 超过 6 岁的剂次照常排（表只到 6 岁），显示与操作同其余剂次
- 同一剂重复标已种：成长页该剂点击即进入编辑（一条记录），不会产生第二条
