# RequireSpec · 云同步后端

## 背景与目标

爸爸妈妈两台手机都要能记宝宝数据（喂奶/尿布/睡眠/生长/疫苗/补剂……），数据不能分裂。目标：在 `backend/` 目录实现一个 **Go 同步服务**，App（Android）通过 HTTP API 对接；App 侧仍是本地优先（Room 本地库为准，联网时增量同步）。

本文只覆盖**后端 + API 契约**；App 侧同步客户端属后续功能（另开 feature）。

## 功能范围

**做**：

1. 家庭与设备：创建家庭（首台设备同时注册）→ 生成配对码 → 其他设备凭码加入
2. 鉴权：长时令牌（Bearer），数据库只存哈希
3. 上行同步 push：批量提交本地变更，服务端按 LWW 落库
4. 下行同步 pull：按游标增量拉取变更（含其他设备的新增/修改/删除墓碑）
5. 设备列表：谁在共记（名字 + 最后活跃时间）
6. 健康检查 ping

**不做**（明确出界）：

- 公开注册/多租户/找回密码等账号体系——只有家庭配对码
- 记录内容的结构校验——payload 是客户端自定义 JSON，服务端只透传（App 升级加字段不用改后端）
- 统计/报表接口——V1.1 统计在端上算
- 推送通知（FCM/长轮询）——App 打开时拉，够了
- 图片/附件同步——V1 无此需求
- 多宝宝路由——record 里带 `baby_id` 字段即可，服务端无感知

## 功能点分解

| # | 功能点 | 说明 |
| --- | --- | --- |
| F1 | 创建家庭 | 无鉴权；入参设备名；出参 family_id + 设备令牌 + 配对码（15 分钟有效） |
| F2 | 配对加入 | 无鉴权；配对码 + 设备名 → 新设备令牌 |
| F3 | 刷新配对码 | 已登录设备可刷新（旧码作废） |
| F4 | push | 鉴权；≤500 条/批，单条 payload ≤64KB；author 由令牌判定，不信任客户端 |
| F5 | pull | 鉴权；`cursor` 起增量，`limit` 分页，`has_more` 提示续拉 |
| F6 | LWW 冲突 | 同 uuid 按 `updated_at`（客户端毫秒时间戳）取新者；不新则跳过并计数 |
| F7 | 设备列表 | 鉴权；名称 + 最后同步时间 |
| F8 | ping | 无鉴权健康检查 |

## 非功能需求

- 单二进制部署（纯 Go，无 cgo），SQLite 单文件存储，零外部依赖
- 家庭间数据严格隔离（一切查询按 family_id 过滤）
- 令牌不明文落库；日志不打印令牌
- 并发安全（HTTP 并发 + SQLite WAL）；服务重启数据不丢
- 接口响应 < 50ms（家庭规模数据量）

## 约束与依赖

- Go 1.25，标准库路由（不引 Web 框架）；SQLite 驱动 modernc.org/sqlite（纯 Go）
- 部署目标：Linux 云服务器（Docker 或 systemd 任一），HTTPS 由反向代理（nginx/caddy）终止——**本 feature 不含部署实施**
- App 对接依据 = design.md 的 API 契约

## 验收标准

1. 两台设备（模拟）经创建家庭/配对后：A push 的记录，B pull 能完整拿到，内容一致
2. 同一 uuid 先后 push 不同 `updated_at`：终态取时间新者；旧者 push 返回 skipped
3. 无令牌/错令牌访问除 ping/创建/配对外全部 401；A 家庭拉不到 B 家庭任何记录
4. `deleted=true` 墓碑能同步（对端据此删本地）
5. 非法输入（坏 JSON、超限 payload、非法 type、空 uuid）返回 400 且不落库
6. `go test ./...` 全绿；`go build` 产出单二进制，默认参数启动即可用

## 待确认

无阻塞性待确认项。两个已决策的取舍（理由见 design.md）：存储用 SQLite（备选 MySQL，表结构是通用 SQL，要迁随时说）；时间戳用客户端毫秒时间戳做 LWW。
