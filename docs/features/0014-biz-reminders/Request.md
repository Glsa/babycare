# 0014 · 提醒实装（FR-13）— 需求录入 + 拍板

日期：2026-10-18 · 来源：用户「完成我的页面里面的待开发的功能。提醒、统计和生长曲线」

## 需求

我的页「提醒设置」从灰置变实装。范围（PRD FR-13）：

| 类型 | 触发 | 默认 |
| --- | --- | --- |
| 疫苗 | 到期前 3 天 / 1 天 / 当天 9:00 | 开 |
| 补剂 | 每个设定时间点（当天起） | 开 |
| 体检/自定义行程 | 提前量（当天 / 前 1 天 / 前 3 天） | 当天 |
| 关键节点 | 满月、百天、半岁、周岁前 1 天（拍照留念 📷） | 开 |
| 喂奶间隔到期 | 距下次喂奶归零（0011 设置） | 开 |

- 全部本地通知，点击直达对应页面；总开关 + 分项开关。

## 拍板（RequireSpec 结论）

1. **喂奶间隔提醒从 V1.1 提前到本期**：0011 数据（FeedIntervalKit + prefs）已就绪，用户点名要提醒，Widget 也已显示倒计时。睡眠间隔提醒不做（夜里误吵）。
2. **调度 = 单闹钟链**：任何时刻系统里只挂一个闹钟（最近的提醒时刻），触发后发所有到期提醒、再排下一个。避免批量 PendingIntent 管理；不精确闹钟（`setAndAllowWhileIdle`），分钟级容忍，免 `SCHEDULE_EXACT_ALARM` 权限。
3. **重排时机**：App 启动、repo.changes（记录/计时变更）、提醒开关变更、闹钟触发后、Widget 兜底闹钟 tick（5/30 分钟顺带）、开机（`RECEIVE_BOOT_COMPLETED`）。
4. **补剂到点就发**，不查当天是否已打卡（打卡本来就在通知点击后的页面上做）；已过时刻（>5 分钟）不补发。喂奶超时提醒对同一「喂奶起点」只发一次（prefs 记已发起点，防重排 spam）。
5. **提前量入口**：自定义行程新建/编辑弹层加 chips（当天/前 1 天/前 3 天）；体检沿用自动生成（默认当天 9:00）。
6. **通知渠道单条**「提醒」；点击路由：疫苗→成长页、补剂→今天页、行程→行程页、节点/喂奶→今天页（复用 pendingSheet 同款 Application StateFlow 机制，新增 pendingTab）。
7. **开关存 prefs**（同喂奶间隔模式）：总开关 + 5 分项（疫苗/补剂/行程/关键节点/喂奶间隔）；非业务记录不随备份迁移。
8. **通知权限**：首次打开提醒设置页请求一次（API 33+）；拒绝不阻断，其余功能照常（只是系统不弹）。
