# RequireSpec · 补剂 + 早教 + 行程回填

需求来源：PRD FR-8（早教）、FR-10（补剂）、FR-12（今日待办来源）、附录 B（早教项目示例）。范围切分与不做清单见 Request.md。

## FR-10 补剂（原文要点）

- 预置 VD3（400IU 提示文案）/ AD / DHA / 铁 / 钙 / 锌 + 自定义
- 方案字段：名称 / 单次剂量 / 每日时间点（多个）/ 开始日期 / 停用
- 每日打卡到点提醒（提醒部分延后）；漏服日历可见；各自独立打卡

## FR-8 早教（原文要点）

- 四大类：视觉 / 听觉 / 大动作 / 精细动作；内置 0~12 月项目库
- 今日推荐按月龄每天 2~3 项，同一项目不连续两天重复
- 打卡（时长选填），当天打卡进今日行程

## 澄清结论（设计拍板）

| # | 问题 | 结论 |
| --- | --- | --- |
| Q1 | 补剂方案与打卡的记录形态？ | 方案 = SUPPLEMENT_PLAN 记录（一条一个方案，长生命周期，occurredAt=开始日期）；打卡 = SUPPLEMENT_LOG 记录（一次一条）。payload 字段 0002 就定义好了，不加字段 |
| Q2 | 打卡怎么算「今天这一顿已服」？ | 同方案名 + 同 planTime + takenAt 落在今天 → 已服。取消打卡 = 软删那条 log。方案名可重复是 V1 已知边界 |
| Q3 | 时间点怎么维护？ | 常用时间点 chips（08:00/10:00/12:00/15:00/18:00/21:00）多选 + 自定义 HH:mm 追加；存 "HH:mm" 字符串，展示/匹配都用它，按字符串排序 |
| Q4 | 早教推荐算法？ | 纯函数：按日期确定性选（同一天永远同结果，不依赖进入时机）；条数 2/3 按日轮换；优先排除昨天打过卡的项目；池子不足时允许与昨天重复 |
| Q5 | 「不连续两天重复」的判定口径？ | 昨天有该项目打卡记录（EDU_CHECKIN，item 相同）即算做过；只看昨天一天（不是滑窗） |
| Q6 | 早教「时长选填」怎么交互？ | 卡片点按 = 直接打卡（无时长）；要补时长在今日记录时间轴的详情里编辑（新增 EduSheet：时长/时间） |
| Q7 | 疫苗临近置顶的口径？ | 状态为待种（已到期）或未到月龄但计划日在今天~+7 天；按计划日升序，今天卡最多显示 3 条；点击跳成长页标已种 |
| Q8 | 月龄怎么算、超龄怎么办？ | 周岁月差（Period 年×12+月）；0~12 月内都有池子；≥13 月池子为空 → 早教卡/推荐整体不显示 |
| Q9 | 补剂方案管理入口放哪？ | 行程 Tab 补剂卡右上「管理」：方案列表（停用开关/编辑/删除）+ 新建（预置 chips + 自定义）。不进通用 RecordSheet 体系（只在行程页用） |

## 验收标准

1. 补剂：方案 CRUD + 停用生效；当日任务 = 进行中方案 × 时间点（开始日期未来的不出）；打卡/取消独立、时间轴可见
2. 早教：推荐按月龄、确定性、避昨天；打卡生成时间轴记录并可编辑时长；≥13 月不显示
3. 疫苗临近：待种 + 7 天内未到月龄的剂次，今天卡与行程 Tab 置顶，点击跳成长页
4. 成长页早教中心卡：本月推荐 + 本周打卡次数
5. 纯函数（补剂任务推导 / 早教推荐 / 疫苗临近）单测全绿，assembleDebug 通过

## 已知边界

- 方案改名后历史 log 按旧名匹配不上（log 快照名字）——V1 接受，打卡匹配按名字+时间点
- 同名方案并存时打卡会互相串——V1 建议避免同名（表单不强制）
- 提醒通知（FR-13）延后，时间点目前只是打卡口径
- 早教库 0~12 月；超龄后卡片消失，历史打卡记录仍在时间轴
