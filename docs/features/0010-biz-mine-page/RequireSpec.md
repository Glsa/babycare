# 0010 · 我的页 — 需求澄清（RequireSpec）

日期：2026-10-18 · 模式：逐题拍板（推荐 + 理由），与 0006~0009 同格式

## Q1 提醒设置：实装还是入口占位？

**拍板：入口行 + 灰置样式，点击提示「提醒功能即将上线」。**

- 理由：FR-13 实装 = 通知渠道 + 疫苗/补剂/节点三类调度（WorkManager/AlarmManager 选型、开机重排），是一整块独立工作，塞进本期会把「我的页」拖成大杂烩。入口先占住设计稿位置，实装时只换跳转。
- 实装时机：V1.0 收口后独立课题（真机冒烟一并验证通知）。

## Q2 深色模式：两态开关还是三选？

**拍板：两态开关——关 = 跟随系统（默认），开 = 深色。**

- 理由：夜里喂奶强制深色是真实场景；「强制浅色但系统深色」的需求几乎不存在。三选（系统/浅/深）要多一个二级弹窗，交互变重，收益低。
- 持久化：SharedPreferences（`theme_dark_override: Boolean`，缺省 false）。设置类数据不进 Room。
- 生效：立即全局生效，无需重启。

## Q3 导出/导入的文件交互？

**拍板：SAF（系统文件选择器）。**

- 导出：`CreateDocument("application/json")`，默认文件名 `babycare-backup-20261018-1930.json`，用户选位置，App 只拿到 URI 写入。不需要存储权限。
- 导入：`OpenDocument`，用户选备份文件，App 读 URI 解析。
- 理由：个人 App 最省事且合规；不引权限、不碰公共目录命名空间。

## Q4 导出内容与导入合并策略？

**拍板：全量记录快照 + uuid/updatedAt LWW 合并（与云同步同一套判定）。**

- 导出内容：`{ version, exportedAt, records: [...] }`，records 含**全部类型含软删墓碑**（保 LWW 语义完整），字段与 Room `RecordEntity` 一一对应（uuid/type/payload 原文 JSON/occurredAt/updatedAt/deleted/author/babyId）。宝宝档案本身就是一条 `BABY_PROFILE` 记录，天然在内。
- **不导**：亲喂计时暂态（meta）——换机恢复「进行中」计时毫无意义且易错；导出纯持久数据。
- 导入合并：逐条 `SyncMerge.shouldApply(local.updatedAt, incoming.updatedAt)`，严格更大才覆盖——与 0001 后端、V1.1 客户端同一语义，导入 = 一次本地「下行」。导入前后台一致，无需「覆盖/合并」二选。
- 导入确认对话框展示规模：「将导入 N 条记录（新增 X / 更新 Y）」，让用户知道会发生什么再点确认。

## Q5 清空数据的确认强度？

**拍板：对话框二次确认（红色「清空」按钮），不要求输入昵称。**

- 理由：个人 App、数据可先导出；对话框讲清后果（「所有记录与档案将被删除，且无法恢复。建议先导出备份」+ 对话框里直接给「先导出」入口）已够。输昵称确认是面向多用户产品的防御，这里过度。
- 清空范围：records 全表（物理删）+ meta 全表（亲喂计时态随 meta 一并清）。
- 清空后：回首启引导页重新建档；Widget 刷成无宝宝占位（走 changes 流）。

## Q6 灰置项与点击反馈？

**拍板：统计与生长曲线、自动备份两行灰置（透明度降低 + 「V1.1」角标），点击弹 snackbar「V1.1 版本提供」。**

## Q7 档案编辑弹层字段与规则？

**拍板：昵称（必填）/ 生日（必填，DatePicker 不许未来）/ 性别（女/男 选）/ 出生体重 kg / 出生身长 cm（选填，小数）。**

- 复用建档页的交互样式（OutlinedTextField + Surface 日期行 + FilterChip）；体重/身长为建档没收的 FR-1 字段，此处补全。
- 保存：走 `repo.update`（同 uuid，updatedAt 推进），第 N 天、疫苗推算随后自动跟随新生日。

## 验收标准

1. 我的页六区块齐全，视觉对齐设计稿帧 07（含深色态）。
2. 档案编辑：改昵称/生日/性别/出生体重身长保存后，今天页第 N 天、成长页等联动正确；生日非法（未来）不可选。
3. 深色开关：开启立即全局深色；关闭回跟随系统；杀进程重启保持。
4. 导出：SAF 选位置成功写入 JSON；文件内容含全部记录（含已删除的墓碑）与档案。
5. 导入：选合法备份 → 确认框报数量 → LWW 合并结果正确（旧数据不被更旧备份覆盖）；坏文件/坏 JSON 明确报错不崩。
6. 清空：确认后所有数据清空回到引导页；Widget 变无宝宝态。
7. 灰置两行不可用但可见，点击有「V1.1」提示。
8. 单测全绿（在 69 基础上新增导入导出与合并用例）。
